## Problem (what densify + study-sim taught)

On a 45-lecture plain-text corpus (LectureBank), CURATE produced:

1. **0 figure pages / thin facts** relative to concepts/analyses — captions live as `Fig. N` / `Table N` lines in vault extractions, not as first-class wiki pages.
2. **Atomic exam claims under-produced** — entity/concept surface grew; caption-grade and one-sentence facts lagged.
3. **Analyses dominate embedding retrieval** — long multi-lecture analyses outrank short facts/sources, so generators never see the needle even when a fact page exists.

Phase-2 extractive golds (`0.4`, `Figure 2`) do not model study use. Study-sim replaces that product gate with personas (student / educator / journalist / academic) and six task families; **CE product arm is `ce_two_stage` (T2)**. CE must own the curator + retrieve fixes so SB can drop parallel paths.

## Design decisions (**locked** 2026-07-20)

### D1 — Caption routing by kind (locked)

| Caption kind | Primary page | Notes |
|--------------|--------------|--------|
| **Figure** (`Fig. N` / `Figure N` / diagram caption) | `wiki/figures/…` with `origin: caption-text`, asset optional | PDF-rendered figures stay `origin: extracted` + asset |
| **Table** (`Table N` captions) | **Always** `wiki/tables/…` | Caption-only tables are still table pages (not facts). Real grids still use `promote-extracted-tables` / multimodal path when present |
| **Fact** (`wiki/facts/…`) | **Optional synthesis**, not the default caption home | Use when (a) this claim only appears in the caption and a short atomic fact helps retrieval/study, or (b) the same claim is described in multiple places and a fact page synthesises them better than any single caption page |

Figure and table caption pages carry `(vault:…)` + source wikilink; link to concepts/entities as usual. Facts that restate a caption use `verbatim: true` when the body is near-verbatim.

### D2 — Caption harvest is a **demand queue + wave mode**, not only prompt prose

Prompt-only densify (SB watchdog) is a temporary operator override. Durable CE behaviour needs:

1. Deterministic candidate discovery (`sweep.py caption-candidates`).
2. A CURATE plan mode that drains it into figures/tables (and optional facts per D1).

Mode name: **`caption-harvest`**, precedence **above** free-form create/repair when the queue is non-empty (after table-audit/numeric-review safety modes, before wire/repair; peer of `figure-extract`).

### D3 — T2 default **on** for needles (locked)

Charter: production retrieval is CE-owned. Ship:

- `query_is_needle(query) -> bool` in `graph.py` (or small helper module for testability).
- Type-priority reorder of `pages` **after** graph expansion, **before** `limit` trim — **on by default**.
- **`two_stage_on_needle: true` by default** — vault-first / primary-type budget when needle; synthesis keeps analyses mid-pack. Optional `two_stage_always` for operators who want it everywhere.

T2 is a **context assembly rank**, not a replacement for BFS or the entity gate.

Config (additive, template merge):

```json
"retrieve": {
  "type_priority": true,
  "two_stage_on_needle": true,
  "two_stage_always": false
}
```

Omit block → same as defaults above.

### D4 — Do not wait on study-sim gate to land code; wait on gate to claim product wins

Code + unit tests ship in CE. Public “study-sim beats raw RAG” claims remain SB-gated. CE CHANGELOG describes the mechanism, not unvalidated benchmark wins.

### D5 — Facts create quota bump is mode-scoped

While `caption-harvest` candidates exist, figure/table (+ optional fact) slots absorb most of the wave. Global permanent raise of create-mode facts quota is **not** required. Prefer queue-driven mode.

### D6 — Release process (locked)

No PR DAG / Graphite stack. Ordered commits on **`main`**, then push + tag `v0.9.2` + GitHub release. Work packages below are commit batches, not pull requests.

### D7 — Implementation hold (locked 2026-07-20)

**Further designs are incoming.** Do not start W1–W5 implementation until those are reviewed and this plan is updated. Plan-assist docs track the hold.

### W1 — Schema: text-only caption pages + `verbatim` facts

**Files:** `template/schema.md`, `SKILL.md` (Figures + tables + facts format), `score_diff.py`, `figures.py` (`check` / `list`), tables-related checks if any, `naming.py` (frontmatter allowlist), viewer (graceful missing asset).

**Behaviour:**

| Field | Rule |
|-------|------|
| `type: figure` | Unchanged |
| `origin` | `extracted` \| `created` \| **`caption-text`** (new) |
| `asset` | Required for `extracted`/`created` when check expects regen; **optional** for `caption-text` |
| `extraction_method` | e.g. `caption_line` for text-only |
| Table caption pages | Live under `wiki/tables/`; may be caption-only (no grid) or full/snapshot tables |
| `type: fact` + `verbatim: true` | Optional bool; body near-verbatim; still needs `(vault:…)` |

**score_diff (locked floors):**

- Figures (incl. caption-text): ≥1 citation, 0 wikilinks required, ≥10 words — no image embed required for `caption-text`.
- Tables: existing tables floors apply; caption-only table pages must still pass.
- Facts with `verbatim: true`: **≥1 citation, ≥1 wikilink, ≥15 words** (not 30).
- Facts without `verbatim`: keep ≥30 words.

**figures.py check:** skip “missing asset” for `origin: caption-text`.

**Tests:** fixture pages for figure caption-text, table caption, verbatim fact floor 15; unit tests on floors + check.

### W2 — `sweep.py caption-candidates`

**Files:** `sweep.py` (hash-guarded — edit in skill source), `evolve_guard.sh` (no list change if already guarding sweep), tests.

**CLI:**

```bash
uv run python3 <skill>/scripts/sweep.py caption-candidates wiki [--limit N]
uv run python3 <skill>/scripts/sweep.py mark-caption-harvested --extraction <path> [--count K]
```

**Algorithm (deterministic):**

1. Walk `vault/**/*.extracted.md` (and plain vault `.md` if no extraction — prefer extracted).
2. Regex (case-insensitive), multi-line tolerant:
   - `Fig(?:ure)?\.?\s*\d+[a-z]?` …
   - `Table\s*\d+[a-z]?` …
   - Optional: lines with `diagram` + caption-like length (keep strict first; expand later).
3. Capture the caption line (and optional following line if continuation).
4. Dedup key: `(vault_path, normalized_caption_hash)` or `(vault_path, fig_or_table_id)`.
5. Exclude if any existing wiki page (facts/figures/tables) already cites that vault path **and** body contains a high-similarity span of the caption (or frontmatter `caption_id`).
6. Rank by: not yet harvested → source distinct citers (reuse figure-candidates demand) → stable vault path.

**Emit JSON:**

```json
{
  "candidates": [
    {
      "vault_extraction": "…extracted.md",
      "kind": "figure|table",
      "label": "Fig. 2",
      "caption": "…",
      "line_hint": 120,
      "distinct_citers": 3,
      "suggested_table_stem": "…",
      "suggested_figure_stem": "…",
      "optional_fact_stem": "…"
    }
  ]
}
```

**Mark:** set on extraction frontmatter `captions_harvested: <ISO>` (or per-label set) so empty harvests do not infinite-loop — same pattern as `figures_extracted`.

**Canary:** none new (sweep already allowlisted). Document new subcommands in SKILL if listed explicitly.

### W3 — CURATE mode `caption-harvest` + prompt policy

**Files:** `SKILL.md` (Phase 1 mode table + Phase 2 protocol), `template/prompts.md` (worker brief template), `epoch_summary.py` optional queue count, `planner.py` if mode enum listed.

**Plan precedence** (insert after numeric-review / before wire):

```
… numeric-review
→ caption-harvest   if caption-candidates non-empty
→ figure-extract    (PDF path; unchanged)
→ wire / repair / create
```

**Execute protocol:**

1. Take top `parallel_workers` candidates.
2. Each worker (worker_model) gets: caption text, kind (figure|table), vault path, surrounding ±N lines, existing concept/entity stems.
3. Worker returns JSON:
   - **figure kind** → `figure_page` required; optional `fact_page` per D1
   - **table kind** → `table_page` required; optional `fact_page` per D1
4. Orchestrator writes via `score_diff --new-page`, scrub_check; light batch review (skip opus unless long).
5. `mark-caption-harvested` per processed extraction.
6. Commit + graph rebuild.

**Create-mode policy tweak (when caption queue empty but densify still desired):**

- Prompt: prefer atomic facts over analyses; analyses only when ≥2 sources already have facts/entities/caption pages for the theme.
- Optional densify override of facts quota — not required to ship.

**Densify operator note:** SB watchdog can shrink once caption-harvest is automatic.

### W4 — Type-aware + two-stage retrieve

**Files:** `graph.py` (`cmd_retrieve`, helpers), optionally pure helpers testable without kuzu, `template/config.example.json`, SKILL QUERY §, tests.

**API:**

- Keep CLI: `graph.py retrieve wiki "<q>" [--route auto|graph|blend] …`
- Flags: `--no-type-priority`, honour config for two-stage.
- Response JSON: `needle`, `assembly`, optional `type_rank` per page.

**Ranking (after seed+BFS+overlap list):**

1. `type_priority` default **on** — stable-sort by `(type_rank, distance, -overlap, path)`:

   | type | needle rank | synthesis rank |
   |------|-------------|----------------|
   | sources | 0 | 0 |
   | facts / figures / tables | 1 | 1 |
   | evidence | 2 | 2 |
   | entities | 3 | 3 |
   | concepts | 4 | 3 |
   | analyses | 9 | 4 |
   | notes/todos | 5–8 | 5–8 |

2. `two_stage_on_needle` default **on**: when needle, force vault stream + ~70% primary types; residual secondary. Ordered partition of already-retrieved candidates — not a second embed if avoidable.

3. `query_is_needle` from SB heuristics (fig/table/caption/passage/quotes) — no LLM.

**Entity gate:** unchanged; runs first.

**QUERY agent guidance:** prefer listed order; primary types over analyses ~2:1 on needles.

**Regression tests:** fact/figure/table beats long analysis on needle query; synthesis still admits analyses; entity abstain green.
